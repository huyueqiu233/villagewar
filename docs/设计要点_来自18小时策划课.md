# villagewar 设计要点（从《游戏策划 18 小时课程》里筛出来的部分）

> 来源：`游戏策划入行_18小时课程总结.md`（P1–P18，BV1hsE16bEHS），只保留**能直接用在 MC 模组**的部分。
> 求职、薪资、文案岗位、战斗帧数据（MC 没有动画取消/前摇体系）等内容不适用，已剔除。

## 一、先立一条总纲：3F（形式服从功能）

> 每做一个东西，先写一句 20 字内的功能诉求；写不出来，就是自嗨。

对 villagewar 的意思是：**每类建筑、每个机制都要能回答“它服务哪个玩法”**。

| 已有内容 | 功能诉求（要能一句话说清） | 现状判断 |
|---|---|---|
| 围墙圈 / 瞭望塔 / 守卫小屋 | 让防守有地形可依、有视野、有火力点 | 已加，但还没让它们“有用”：袭击不会走门、塔没有射击优势 |
| 大农田 + 堆肥桶 | 村庄产粮 → 村民繁殖 → 人口增长 | 成立 |
| 掠夺者营地 | 反攻目标：打掉战旗换安全期 | 成立，但营地内部没有关卡设计 |
| 势力锁定 | 让玩家有归属，不能随便换边 | 成立 |
| 工人/铁傀儡上限 | 防止村子无限自保，逼玩家参与 | 成立 |

**下一步自检**：新建任何东西前，先填“功能诉求”这一列，填不出就不做。

## 二、系统四分法与核心循环（决定该做什么、不该做什么）

**核心循环**（villagewar 现在的）：
```
选势力 → 村子自动发育 → 掠夺者来袭（营地等级驱动）→ 防守/反攻
      → 打掉战旗 → 安全期 → 村子继续发育 → 更高等级来袭
```

课程里最关键的一句：**“达标瞬间必须立刻立更高目标”**，否则玩家觉得“到头了”。

我们现在的缺口：
- 打掉营地后只有“10 分钟安全期”，**没有下一个目标**；
- 村子发育到上限后，玩家没有继续投入的理由；
- 缺少“目标 → 奖励 → 新目标”的闭环。

**可落地的改法**（按性价比排序）：
1. 营地重建后**等级 +1**（现在固定回到 0），形成“你打一次，它更狠一次”的压力曲线；
2. 打掉营地给**势力点数**（可换装备/材料），点数商店是下一个目标；
3. 村子规模到 3/5/8 座房子时给**里程碑奖励**（不是自动发，让玩家去领/去用）。

按课程的四层分类，我们该只做**核心系统**（防守/反攻/势力）与**延伸系统**（农田、铁傀儡、道路）；成就、图鉴这类“辅助系统”在模组阶段不做。

## 三、玩点八步：把“防守”从一个词变成可调参数

课程给的八步：功能诉求 → 运行机制 → 玩家技巧 → 玩家输入 → 核心控制参数 → 关卡模块 → 提示反馈 → 演出。

以“防守一波袭击”为例，落到 MC：

| 步骤 | villagewar 的对应 |
|---|---|
| 功能诉求 | 让玩家在有限准备时间里做取舍（修墙还是囤兵） |
| 运行机制 | 营地等级决定波次规模；袭击在玩家附近村庄触发 |
| 玩家技巧 | 站位、卡门、铁傀儡调度、提前拆营地 |
| 玩家输入 | 只有移动/攻击/放置方块，别设计需要新按键的机制 |
| **核心控制参数** | 见下表 |
| 关卡模块 | 围墙门洞、瞭望塔、守卫小屋、农田位置 |
| 提示反馈 | 袭击预警、剩余波次、村子状态提示 |
| 演出 | 号角/钟声、红字警告、掠夺者旗帜 |

**核心控制参数表（三档，直接照课程的难度矩阵做）**

| 参数 | 低（Lv0–1） | 中（Lv2–3） | 高（Lv4–5） |
|---|---|---|---|
| 每波掠夺者数量 | 2–3 | 5–8 | 10–22 |
| 波次间隔 | 90 秒 | 60 秒 | 30 秒 |
| 预警时间 | 30 秒 | 15 秒 | 5 秒 |
| 营地距离 | 1500 格 | 1200 格 | 800 格 |
| 夜袭概率 | 10% | 30% | 50% |
| 是否拆门 | 否 | 偶尔 | 会 |

**参数必须“纯粹”**：只改这张表里的数字，不要偷偷加新机制；否则调平衡时说不清是哪个参数起的作用。

## 四、数值：用一个“标准人”反推，而不是拍脑袋

课程 P6/P8 的流程：`设计定位 → 属性分配 → DPS 粗算 → 理想输出序列 → 对抗分析 → 演算 → 真机 → 归因 → 调整`。

MC 版“标准人”定义（写死，之后所有数值都对着它算）：
- 铁套 + 铁剑 + 盾：约 **8 点/秒** 有效输出，**15 点**有效生命；
- 钻石套 + 钻石剑：约 **14 点/秒**，**25 点**生命；
- 有铁傀儡支援时，村庄火力 **+50%**。

反推规则：
- 一波袭击的总血量 ≈ 标准人 **40–60 秒**能清完（低于 30 秒没压力，高于 90 秒疲劳）；
- 掠夺者单体血量 = 总血量 / 数量，**数量越多单体越脆**（避免“又肉又多”）；
- 营地等级每 +1，总血量 ×1.15（**边际递增，不是线性**），逼玩家升级装备而不是堆时间。

课程还有两条硬教训可直接用：
- **不要只加一个维度**：只加数量会变成“排队送”，要同时加数量、加远程比例、加破门能力；
- **给对手加克制手段，优于削弱自己**：想让防守变难，就给掠夺者加“拆墙/点火/绕后”，而不是削弱铁傀儡。

## 五、关卡：把营地做成一段 5–10 分钟的“可玩段落”

课程 P18 的命题关卡三要素：**剧情 / 环境场景 / 目标挑战能力**，互为犄角。

现在的营地只是“栅栏 + 帐篷 + 战旗”，没有关卡结构。按三要素重排：

- **环境场景**：外围木墙只留一个门（chokepoint）→ 门后是营房（小怪）→ 中间是囚笼（人质/奖励）→ 最里面是高台战旗（目标）。玩家必须先破门、再清场、最后登高。
- **目标挑战能力**：考验“先拆哪”的判断——拆门引来全部，绕后拆旗可以少打。
- **剧情**：被掳走的村民/铁傀儡在笼子里，救出来会给村子加成（把“打营地”和“村子运营”连起来）。

**判据**（课程原话）：合理性与反认知差、目标割裂、有效奖励。营地设计里最该避免的是**目标割裂**——玩家想要的是“安全期”，我们却让他去打一个纯刷怪场。

## 七、明确不搬的部分

- 求职话术、薪资、作品集、面试（与模组无关）；
- 战斗帧数据（前摇 12–15 帧、卡针、取消权重）——MC 没有这套动画取消体系；
- 文案岗位方法论——但**世界观那套（三道约束、三层冲突、logline）可以借来做赤潮/苍蓝的势力背景**，属于可选项，优先级低于玩法。
